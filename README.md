拆解架构骨架——从 Agent Loop 到闭环学习的底层设计
想做 AI 数字员工，第一步不是急着部署，而是理解 Hermes Agent 为什么能在众多 Agent 框架中脱颖而出。核心差异不在功能清单，而在架构设计哲学。

与主流框架的根本区别
市面上大多数 Agent 框架解决的命题是“怎么让 LLM 更好地调用工具”。Hermes Agent 解决的命题不同：怎么让 Agent 越用越聪明。这个方向差异决定了整个架构的设计取舍。Hermes Agent 由 Nous Research 于 2026 年 2 月开源，采用 MIT 协议，GitHub Star 数已突破 11 万，贡献者超过 240 人。

闭环学习：从 Day 1 融入核心
Hermes Agent 最核心的架构创新是闭环学习，它不是事后打补丁，而是从第一天就融入核心架构。闭环学习包含五个环节：任务完成后 Agent 自主判断什么值得记住（策划记忆）；识别重复模式自动生成 Markdown 格式的 Skill 文件（创建 Skill）；现有 Skill 失败时自动优化（Skill 自改进）；按需检索历史对话（FTS5 召回）；从行为推断用户偏好（用户建模）。

这套机制对应认知科学的三种记忆类型：情景记忆（会话历史）、语义记忆（MEMORY.md 持久事实）、程序性记忆（Skill 文件），形成了完整的“认知—记忆—行动”闭环。

三层 Prompt 与思考-行动循环
系统提示词分为三层：stable 层定义 Agent 身份和工具使用指导，生命周期内基本不变；context 层承载项目上下文文件；volatile 层包含记忆快照、用户画像等每轮对话都可能变化的内容。这个设计的核心考量是缓存命中率——将不变的部分与频繁变化的部分分开，对上游 LLM 提供商的 prefix cache 友好，能明显减少重复 token 计费。

对话循环采用经典的 ReAct 模式：观察、推理、行动、反馈，每一轮循环包含组装提示、模型推理、工具调用与结果反馈、循环终止四个基本动作。理解这套循环逻辑，是后续配置和调试的基础。

入门阶段的核心任务不是记住所有功能，而是建立对“闭环学习 + 分层设计”这一架构哲学的直觉。全套课程完结可学，建议第一遍先建立框架认知，第二遍再对照源码逐层验证。
